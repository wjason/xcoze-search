# 免 Key、DeepSeek 与 Smart：真实任务复测

**简体中文** | [English](2026-11-03.en.md)

测试日期：2026-11-03。测试环境：本机 macOS、Python 3.10，使用已有 DeepSeek Key；没有修改密钥或已保存偏好。代码基线为 `e758498`（v0.4.1），优化轮使用该基线上的 v0.5.0 调度实现；原始记录里的运行版本仍为当时的 0.4.1。可审阅的[脱敏数据](2026-11-03.data.json)保留各轮时间、URL、调用记录和人工判断，不包含密钥或网页摘录。

## 结论和实际修改

付费源在这组任务中更快，但没有每题都找到更合适的资料。原 Smart 只在空结果或失败时换源，无法改善“有结果但缺官方证据”的情况。GitHub/HN 定向选路有效，尤其是近期 HN 讨论。

- 通用免 Key 搜索改为 Exa 托管 MCP 优先；Bing RSS、DuckDuckGo 保留备用。本次 Bing 在三题上返回完全跑题的非空内容，不再适合默认首选。
- quality 的最新信息/官方规则任务允许在原有两源预算内补一个来源：本机实际为 DeepSeek → Exa 免 Key。普通查询、显式指定来源、GitHub/HN 专用路线仍按原条件停止。免费/平衡策略不强制双源。
- 给实验性 RSS/HTML 增加保守的零主题词重合检查，返回 `irrelevant_results` 后自动备用；它不判断事实、完整性或中文语义。少于两个有效拉丁词时跳过，不能宣称消除了所有跑题结果。
- Agent 根据原问题使用内部 `--intent reference|current`；用户无需选择模式。价格、规则、最新版本和内容冲突需要读当前官方页面，不能只凭搜索摘要作答。

这是一次小样本迭代；没有由这些结果推导全网准确率或永久来源排名。

## 方法与限制

先固定六道问题和判读条件，跑原版，再跑只调整免 Key 顺序的一轮，最后跑包含意图补充的版本。随后冻结调度，增加两道中文留出题。三种模式逐题串行，轮换执行先后；每源最多 5 条、零重试，请求超时 15 秒，自动调用调度预算 31 秒、最多两源。这里的诊断预算与发布默认 45 秒不同，参数在记录中保留。

免费模式只使用免 Key 适配器；DeepSeek 模式固定单源；Smart 使用实际已配置的 DeepSeek 及公开路线。HN 的平台路线使用原生 UTC 日期筛选；DeepSeek 使用文档支持的 `after:/before:` 语法加站点限定，查询全文保留。这比较的是完成同一任务的适配路径，并非强迫所有接口接受同一个请求体。

耗时是脚本内检索墙钟时间，排除进程启动、答案生成和后续原文核验。每题每轮一次，没有随机网络抽样、置信区间或并发压测。远端缓存、索引变化、执行顺序和已有连接都会影响结果；后续轮明显更快，不能把差异全部归因于代码。

判读分别看相关性、原始来源、是否支持所问细节、时间要求、是否还需读原文。API 成功、非空和命中官网均不等于答案正确。公开数据保留 URL 与人工说明；本地复核使用的最多 1800 字符/条摘录可能截断，超出部分没有被当成已读。

## 六题优化后结果

| 真实问题 | 免 Key | DeepSeek 单源 | Smart |
|---|---|---|---|
| DeepSeek Search 当前收费，空结果/失败是否收费？ | 找到官方指南，继续读计费段落 | 多为第三方内容，混有历史免费期说法 | 补到官方指南，继续读计费段落 |
| Python 最新稳定版和发布日期 | 官方版本列表给出版本和日期 | 找到官方下载页，摘要不足以确认最新补丁 | 补到官方版本列表 |
| TaskGroup 抛错时其他任务及最终异常 | 官方文档、实现代码 | 实现镜像和旧官方提交归档；需核对当前文档 | 补到当前官方文档与实现 |
| anomalib 官方仓库是否支持 OpenVINO | 仓库正确，元数据不足，需读 README | 官方仓库安装/README 内容包含相关支持 | 走仓库接口，需读 README |
| 最近七天 HN 的三条 AI 讨论 | 5 条讨论，均在指定日期区间内 | 本次为空 | 平台接口取得 5 条，不调用付费源 |
| Node.js 当前最新 LTS 主版本和代号 | 官方发布记录可用 | 近期二手报道，需要官方核验 | 补到官方发布资料 |

当日核验基准为 Python 3.15.2（2026-10-25）及 Node.js v26 Lithium LTS。这是测试日期的快照，后续使用必须刷新。[Python 官方下载页](https://www.python.org/downloads/)、[Node.js 官方版本页](https://nodejs.org/en/about/previous-releases)。

TaskGroup 的普通非取消异常会取消其余任务并在等待后组合抛出；特殊异常和版本细节以[当前文档](https://docs.python.org/3/library/asyncio-task.html#task-groups)为准。不能把普通 ExceptionGroup 解释扩展到所有异常。

## 时效性：两道中文留出题

调度冻结后执行，未再根据这两题修改来源顺序。

- **SQLite WAL 能否多个写事务同时写入、读写并行？** 三种模式都有相关结果；免 Key/Smart 找到标准 WAL 官方页，同时也返回 BEGIN CONCURRENT 分支资料。两者不能混为默认能力。标准 WAL 允许读写并行，同一时刻只有一个写事务；[官方 WAL 文档](https://www.sqlite.org/wal.html)和[可选分支说明](https://sqlite.org/src/doc/begin-concurrent/doc/begin_concurrent.md)需分别阅读。
- **GitHub Actions 私有仓库当前怎么计费？** DeepSeek 返回的官方域名索引摘要仍使用固定免费分钟的旧措辞；免 Key/Smart 补到当前官方“所含计算用量”的说明。当前页面核验确认新措辞。该例说明官网 URL 也可能伴随旧索引片段，双源结果冲突需要读[当前计费页](https://docs.github.com/en/billing/concepts/product-billing/github-actions)和[套餐用量页](https://docs.github.com/en/billing/reference/product-usage-included)，不能按来源数量投票。

HN 的时间筛选有结构化日期可检查；其余页面大量 `published_at:null`。未知日期保持未知，不能当成旧内容，也不能凭检索成功标为最新。当前版本和规则通过原文核验，本次没有测量各搜索引擎的普遍索引延迟。

## 耗时与费用

六题各一次检索，单位秒；中位数是六种不同任务的样本汇总，不代表延迟服务等级。

| 轮次/模式 | 中位耗时 | 范围 | 实际 HTTP 次数 | DeepSeek 非空成功次数 | 搜索费估算 USD |
|---|---:|---:|---:|---:|---:|
| 原版免 Key | 0.90 | 0.50–0.99 | 6 | 0 | 0 |
| 原版 DeepSeek | 0.48 | 0.28–0.64 | 6 | 5 | 0.00375 |
| 原版 Smart | 0.69 | 0.25–0.85 | 6 | 4 | 0.00300 |
| 首次优化免 Key | 2.65 | 0.38–4.71 | 6 | 0 | 0 |
| 最终免 Key | 0.66 | 0.40–1.57 | 6 | 0 | 0 |
| 最终 DeepSeek | 0.50 | 0.32–0.58 | 6 | 5 | 0.00375 |
| 最终 Smart | 1.46 | 0.24–1.94 | 10 | 4 | 0.00300 |

留出两题：免 Key/DeepSeek/Smart 中位数分别 1.09/0.56/1.61 秒，HTTP 2/2/4 次，搜索费估算 0/0.00150/0.00150 美元。

最终 Smart 比原 Smart 多 4 次免 Key 请求，仍是 4 次 DeepSeek 计费成功；平台任务省去付费搜索，官方/最新信息任务增加互补来源和等待。不能据此推断对所有任务节省固定比例。

估算采用当日[官方 Search/Fetch 计费规则](https://api-docs.deepseek.com/guides/search/#billing)：每 1000 次成功请求 0.75 美元，空结果、失败和超时不计费。按原始响应是否非空计数，早于站点过滤；不是根据最终展示条数推算。服务未返回账单金额，以上均不是账单核对。模型 Token、宿主订阅和本地计算费用未知，保持 `null`；免 Key 只表示没有本工具的用户 Key API 费用。

全部四轮共 60 个模式单元、66 次搜索 HTTP、31 次 DeepSeek 非空成功，已知搜索费估算总计 0.02325 美元。另做 5 个已知页面的原文读取核验，共 6 次 HTTP（5 次 Jina，1 次 GitHub 403）；没有额外带 Key Fetch。Python 下载页在 24000 字符处截断，但所需版本/日期位于已读部分；不声称读完整页。读取耗时未混入检索表。
