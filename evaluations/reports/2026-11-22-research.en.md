The corpus contains thirteen normal research tasks and three deliberate evidence-gap cases. Exa, Parallel, keyed services, host search and browser were disabled during runtime. Search and reading shared request/time limits. Essential-term checks apply to returned passages; finding a keyword in a body is not answer verification.

Deliberate negative cases require a narrow original-publication range, an absent exact marker, and a one-request limit. They retain date conflict, missing terms and unread-original/budget gaps respectively rather than presenting links as complete research.

## Changes supported by the checks

- Follow a notice directory's actually published body URL, counting both requests.
- Cover previously unrepresented terms in passages rather than repeated headings. Deadline questions prioritize explicit labels with adjacent dates.
- Select existing Rust method IDs without inventing links.
- Group tracking variants of one document while retaining providers, version paths and possible republications; never compare vendor scores.
- Keep native-reader denial/cooldown per host. PDF uses existing tooling; unread attachments remain separate.

## Public-source checks

A separate run checked 89 public actions: 79 passed, seven were limited and three had no hits. This checks each endpoint, including anonymous Exa/Parallel, separately from the research run that disabled both.

The [status page](../../references/source-status.en.md) separates scope, check date and result. The [public snapshot](../../references/source-health.json) excludes query bodies, credentials and account errors. CLI checks older than seven days are stale. The weekly workflow regenerates the snapshot and bilingual status pages.

The previous hosted check failed because a valueless image alt attribute introduced None into text extraction. Missing alt text is now empty text; each action and progress checkpoint is retained, so one adapter failure does not discard the whole run.

## Runtime and release checks

257 offline tests cover extraction, published body/method links, dates, search/body separation, deduplication, denial stops, per-host cooldown, task budgets, update integrity/backups and stale checks. Runtime, Skill metadata, package and release notes use v0.10.0.

The normal package contains runtime code and usage documents; historical corpora and evaluations remain in the source archive and repository. SHA-256 manifests verify files. Installation and restore do not change configuration keys or preferences. Multi-platform offline checks and live samples remain distinct; one local success is not a promise for every network.

## Reproduce

```bash
python3 evaluations/evaluate_research.py --live --output /tmp/xcoze-research.json
python3 evaluations/check_sources.py --live --output /tmp/xcoze-public-check.json --health-output references/source-health.json
python3 evaluations/build_source_status.py
```

Without `--live`, evaluations produce offline plans only. Fixed dates and rolling list windows may diverge in future runs; retain failures. See [research workflow](../../references/research.en.md) and [installation](../../INSTALL.en.md) for usage, reading scope and upgrades.
