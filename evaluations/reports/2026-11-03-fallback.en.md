## Acceptance outcome

**Free-mode paid-search isolation and simulated routing recovery passed. Actual local-browser search availability did not pass on this network.** Simulated browser results are not live retrieval evidence.

Six keyed providers had in-memory synthetic keys. A pre-transmission guard rejects keyed providers/nonempty credentials. No user credential file is read; browser children receive no provider keys/cloud-browser/AI gateway configuration. Quota HTTP/MCP errors persist a pause, skip later calls and permit a later probe. Application limits do not invent HTTP 429. Retry-After is honored; absent guidance, 15 minutes precedes probing, not guaranteed quota reset.

Healthy APIs never launch a browser. A failed complement keeps first-source evidence without starting a browser. Explicit choices, saved limits and disabled sources remain effective. Injected Exa exhaustion plus an irrelevant feed recovers with a simulated browser; the next query skips paused Exa. Both have zero keyed attempts. Real Bing browser tests returned a shell/timeout and were correctly unsuccessful, without identity changes, login-state imports or challenge solving.

135 local offline tests passed; 15 new tests cover quota injection, cross-query pauses, free isolation, API priority, lazy browser execution, sanitized environments/fixed commands/cleanup, budgets/preferences and protocol errors. These do not establish ongoing site availability.

## Balancing speed and depth

| Condition | Default route | Browser |
|---|---|---|
| Matching native platform API | Native public API | None on success |
| Ordinary Smart with enabled keys | Configured API | None on usable results |
| Reference/current complement needed | Second API within budget | Never for complementing existing evidence |
| No usable API results, browser compatible | Up to two API routes then browser | One navigation and close |
| Known Exa limit | Skip Exa, try compatible APIs | Still last |
| Recent browser failure/challenge | Pause instead of reopening | 60-second/15-minute pause |

Usable means a valid nonempty response plus conservative mismatch checks; the Agent still verifies semantic support and truth. Explicit current/saved browser-source selection can override default order.

Defaults: three total sources, 45-second scheduling budget, 8-second auto API caps, 15-second browser work further clipped to --timeout/remaining schedule, plus up to 6 seconds close grace. Lower saved caps are retained; cap 2 means one API plus browser. Without a browser, up to three APIs. Network/DNS/socket behavior is not a hard process service-level deadline.

Normal searches do no online health probe, browser startup, model reranking or dependency installation. Browser work uses a unique anonymous session, empty config and fixed open/wait/DOM-eval/close commands, never agent-browser chat or personal profiles. Close failure is flagged, with a 20-second idle shutdown; cleanup is not falsely acknowledged.

Diagnostics used --timeout 8, clipping browser work to eight seconds rather than its released 15-second default. API failures in live-browser tests were injected locally; Exa was not actually exhausted and Bing RSS/DDG were not sent real requests. The real API observation is a separate anonymous Exa request. Browser resource subrequests are unknown/null, not one fictional HTTP; API budget, navigation and commands remain separate.

The real API path started zero browsers. The slower failed fallback supports API-first, one attempt and cooldown. Browser search did not yield acceptable results here, so no universal recovery or browser-quality claim is made.

## Cost and limits

The verified invariant is zero user-keyed search API attempts, not zero model/subscription/compute/network costs. Smart/quality can still use enabled keys under existing preferences; free never upgrades to keyed Exa or another paid source.

Exa's hosted anonymous MCP has a limited free search/fetch tier: [official docs](https://exa.ai/docs/get-started/exa-mcp). The browser uses existing [agent-browser](https://agent-browser.dev/) and local Chrome without a self-hosted index. Website/network refusal remains a reported gap, not a reason for session/proxy rotation or challenge solving.
