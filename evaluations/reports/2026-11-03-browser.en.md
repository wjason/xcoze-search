# Browser fallback: real-page diagnosis and acceptance

[简体中文](2026-11-03-browser.md) | **English**

2026-11-03. Baseline `2cdd04e`; released as v0.7.1. The browser set ran in the development tree while its version still read 0.7.0; the API-priority probe used 0.7.1. Environment: macOS ARM64, agent-browser 0.27.0, Chrome 156.0.8078.80. [Data](2026-11-03-browser.data.json) omits bodies, cookies, keys, challenge URLs and raw upstream errors. The earlier [quota/shell/timeout report](2026-11-03-fallback.en.md) remains unchanged.

## Diagnosis

1. **Existing nodes were not visible results.** Bing returned HTTP 200 and ten result nodes, but `#b_content` and descendants had `visibility:hidden`; anchor innerText was empty and the screenshot showed only the search header. The old readiness predicate fired on node existence. Later visible responses were also unrelated. Hidden text and unrelated links were not accepted as task evidence.
2. **An explicit index miss looked like loading.** The 360 GitHub page had completed and displayed its no-match message, but the old wait still consumed about 10.29 seconds. The new path returns an explicit empty list without calling it a loading timeout or applying a source-wide failure cooldown.
3. **Startup/navigation were opaque.** One old open(URL) took about 20.18 seconds while Performance Navigation loadEventEnd was about 2.94 seconds. Longer page waits alone do not explain all latency. Launch, navigation, visible readiness, extraction and close are now separate timed stages. This does not fully reconstruct the network causes of the two historical v0.7.0 timeouts.
4. **External restrictions differ from parser errors.** DDG really requested verification, Yahoo returned an HTTP error and Mojeek timed out. None passed; no challenge solving or identity rotation was attempted. Bing's unrelated results are not fixed by a selector, so browser fallback now defaults to the working 360 path while retaining explicit Bing/Google options.

## Changed behavior

APIs remain first. Successful API evidence prevents browser startup. An isolated anonymous session launches a blank page, schedules one navigation through a fixed template, then waits for visible organic rows with nonempty titles. Queries enter only as encoded URL data. 360 organic destinations come from data-mdurl; ads, AI cards and internal engine links are excluded, without visiting each target.

Explicit no-match pages, hidden placeholders, browser network pages, verification and action timeouts have separate outcomes. Conservative English/Chinese topic checks reject obvious mismatches, without semantic scoring. Work remains capped at 15 seconds plus up to 6 seconds close grace, with no engine rotation. Stage timings and close acknowledgments are retained; browser resource HTTP counts remain unknown.

Session/configuration/command use follows the [official reference](https://agent-browser.dev/commands) and the installed version's skills get core --full. No tool upgrade or personal browser/configuration change was required.

## Speed and limits

A separate normal automatic free search returned Exa documentation/CPython sources in about **1.25 seconds**, with **zero browser launches**. Browser tasks took about 3.4–3.8 seconds, so API priority remains useful. One browser navigation is not one HTTP request; browser subrequests stay null/unknown. Zero keyed search API attempts does not cover model/host subscription or local compute costs. After installation, a v0.7.1 CPI search succeeded again in about 4.63 seconds with zero keyed API attempts and acknowledged close.

This machine now has positive live browser evidence, without multi-network or real Windows/Linux runtime acceptance. English-document ranking, mixed result languages and GitHub coverage remain limited; index dates may be stale. The Agent still needs to assess answer support and read current primary sources. This report does not establish browser superiority or universal reliable real-time search.

```bash
python3 scripts/evaluate_browser.py --live --output ../browser-live.json

python3 -m unittest discover -s tests -q
```

The first command requires installed agent-browser/Chrome and real network access. The latter two are offline regressions, not substitutes. 141 offline tests pass, including hidden rows, explicit no-match without cooldown, Chinese mismatch, timeout classification, stage counts, fixed navigation and explicit live opt-in.
