# 浏览器兜底：真实页面排查与验收

**简体中文** | [English](2026-11-03-browser.en.md)

日期：2026-11-03。基线 `2cdd04e`，修正发布为 v0.7.1。浏览器题组在版本号仍为 0.7.0 的开发工作树执行，API 优先复测使用 0.7.1；脱敏数据分别记录。环境为 macOS ARM64、agent-browser 0.27.0、Chrome 156.0.8078.80。[数据](2026-11-03-browser.data.json)不含正文、Cookie、Key、挑战 URL 或原始上游错误文本。此前[限额模拟与真实受限报告](2026-11-03-fallback.md)保持原样。

## 问题定位

1. **节点存在不等于结果显示。** Bing 返回 HTTP 200、10 个 `li.b_algo` 节点，但 `#b_content` 及结果继承 `visibility:hidden`，标题 `innerText` 为空，截图仅有搜索栏。旧 READY 只检查节点存在，提前提取后报空结果。稍后显示的结果还出现明显跑题；没有用隐藏文本或无关链接充当成功。
2. **明确无匹配被误当成未加载。** 360 的 GitHub 查询页面已经完整显示“抱歉，未找到相关搜索结果”，旧等待仍耗费约 10.29 秒。现在该页面可直接返回空列表，和空壳/隐藏结果分开，避免错误地触发整个浏览器来源的失败冷却。
3. **启动与导航合并，缺少阶段定位。** 一次旧 `open(URL)` 用时约 20.18 秒，而页面 Performance Navigation 的 loadEventEnd 为约 2.94 秒；单纯延长页面等待不能解释全部耗时。现在分开启动、发起导航、等待可见结果、提取、关闭，并记录各阶段时间。未声称已经完整重建 v0.7.0 两次历史超时的网络链路。
4. **网站拒绝访问与解析问题不同。** DuckDuckGo 实际返回验证页，Yahoo 出现 HTTP 错误，Mojeek 探测超时；这类结果没有记为成功，也没有求解验证码或切换身份。Bing 的结果异常不能仅用选择器修复，因此浏览器默认改为本次可用的 360，保留显式 Bing/Google。

## 修正后的行为

- 正常查询继续优先原生/商用或免 Key API；已有 API 证据不再启动浏览器。
- 浏览器采用独立匿名会话：空白页启动、固定脚本安排一次导航、等待可见且标题非空的自然结果。查询仅作为编码后的 URL 数据，不是 shell 或任意页面脚本。
- 360 只取自然结果标题、摘要和 `data-mdurl` 目标网址；排除广告、AI 卡片及搜索引擎内部链接，不增加目标链接逐条跳转。
- 明确无匹配返回 `browser_explicit_no_matches:true`；隐藏结果、网络错误页、验证码、命令超时分开分类。英文/中文的保守主题词检查只拒绝明显跑题，不充当语义评分。
- 工作预算仍默认 15 秒，另最多 6 秒关闭宽限；一次调用不轮换引擎。阶段耗时和关闭确认可见，HTTP 资源子请求数量仍为未知。

agent-browser 的会话/配置与命令依据[官方文档](https://agent-browser.dev/commands)及本机版本附带的 `skills get core --full`。未依赖最新版特有命令，也未更新用户的浏览器工具或个人配置。

## 真实问题结果

下表是最终一次固定题组，全部页面/HTTP 响应真实，没有模拟传输。每题各一次，不是延迟排名或普遍准确率。表格不包含此前诊断探测的耗时。

| 实际信息需求与查询 | 结果 | 搜索耗时（含关闭） | 付费 API 尝试 |
|---|---|---:|---:|
| TaskGroup 文档；`Python TaskGroup site:docs.python.org` | 返回官方 asyncio-task 文档，含 TaskGroup 摘要 | 3.82 秒 | 0 |
| 2026 年 9 月 CPI；限定 stats.gov.cn | 返回国家统计局对应发布页 | 3.43 秒 | 0 |
| 新能泰山 2026 年第三季度报告 | 返回中财网公告转载及相关来源；不冒充公司官方页面 | 3.40 秒 | 0 |
| agent-browser GitHub 仓库公开索引 | 360 明确无匹配，覆盖检查未通过 | 3.30 秒 | 0 |
| 真实自动兜底：DDG HTML → browser | DDG 返回 HTTP 202 验证响应；browser 取得 TaskGroup 官方文档 | 3.61 秒 | 0 |

自动兜底的内存偏好明确禁用 Exa/Bing，让 DDG 实际请求后才允许浏览器；不是注入 API 失败，未修改用户偏好。该题实际为 1 次免 Key API HTTP、1 次浏览器导航、5 个本地命令，关闭确认成功。六家带 Key 服务都放入合成凭据，传输守卫拒绝带 Key 来源和非空 Key；所有真实请求都未使用用户 Key。

三个核心检索和自动兜底通过；GitHub 是额外的公开索引覆盖检查，`required:false`、`accepted:false`，没有计为通过。平台题仍应优先对应原生 API。结果较弱的两种 TaskGroup 查询、GitHub 初次无匹配、首版评估器偏好字段错误的无效自动链路均保留摘要；修正字段后有离线回归覆盖。最终把查询缩短为 `Python TaskGroup`，没有降低预设来源/主题标准。

## 速度与边界

同轮追加的正常免费自动搜索由 Exa 免 Key约 **1.25 秒**返回官方文档和 CPython 来源，**浏览器启动 0 次**。浏览器三题约 3.4–3.8 秒，仍是较重的补救路径；保留 API 优先比一开始启动浏览器更合理。一次导航不等于一次网络请求，浏览器 HTTP 子请求数为 null；模型、宿主订阅和本机计算不在“零付费搜索 API 调用”保证内。安装到本机 Skill 目录后，以 v0.7.1 再次真实检索同一 CPI 问题，约 4.63 秒成功；0 次带 Key API，关闭正常确认。

本机真实可用性已有正面证据，但没有跨网络、Windows/Linux 真实浏览器验收。360 的英文文档排序、多语言结果及 GitHub 公开索引覆盖仍有限；索引日期可能过期。API 或浏览器返回来源后，Agent 仍要判断是否回答了问题，并读取必要的当前原文。不能把本报告当作浏览器优于接口或所有实时搜索都可靠的证明。

第一条需要已安装的 agent-browser/Chrome，实际联网；后两条是离线回归，不代替第一条。141 项离线测试通过，含隐藏节点、明确无匹配不冷却、中文明显跑题、CLI 超时分类、阶段计数、固定导航模板和评估器必须显式启用网络。
