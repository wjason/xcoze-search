# 公开平台入口实测与接入取舍

**简体中文** | [English](2026-11-05-public-platforms.en.md)

日期：2026-11-05，Asia/Shanghai。发布版本：v0.8.0。目标是增加 Agent 可直接取得的公开资料，保持低延迟、无需 Key，同时明确搜索、热点发现与正文阅读各自能做什么。

## 本轮接入

| 真实问题 | 实际适配路径 | 结果数 | 端到端耗时 | 取得的证据 |
|---|---|---:|---:|---|
| B 站现在有哪些热搜词？ | bilibili-trending | 5 | 0.224 秒 | 公开热词、热度字段与搜索链接；不是热门视频排行 |
| 知乎现在有哪些热议问题？ | zhihu-trending | 5 | 0.280 秒 | 热榜问题链接、摘录与显示热度；没有读取答案 |
| V2EX 有哪些热门话题？ | v2ex-trending | 5 | 0.597 秒 | 话题标题、节点、创建时间和回复数；没有读取正文/回复 |

安装后复测：B 站与知乎继续成功；V2EX 随后返回 403（约 0.635 秒、1 次 HTTP），工具按规则暂停 15 分钟。下一次 V2EX 调用直接返回 source_cooldown、0 HTTP，未改 Cookie、切换浏览器或调用付费接口。本轮不能将 V2EX 描述为当前持续可用。

上述每题都通过实际 `run_trending` → 共享 HTTP 传输 → 真实端点完成，各一次请求；无带 Key API、Cookie 或浏览器。表中问题说明对应动作，不代表所有 Agent 宿主的自然语言自动触发都已验收。耗时包含本机适配、限频检查与网络，不是仅服务端时间。单次本机结果不能推导长期可用性或延迟分位数。

榜单按源返回顺序输出，B 站显式商业标记会被过滤，序号可能有缺口。热度单位不跨站比较；检索时间不当作源更新时间。B 站/知乎发布时间未知保持 null，V2EX 使用话题创建时间而非榜单更新时间。即使本次返回全部请求条数，也不宣称取得全站完整榜单。

## 小红书、微博与受限入口

| 探测/实搜 | 本次结果 | 处理 |
|---|---|---|
| 微博 `ajax/side/hotSearch`，匿名请求 | HTTP 403，约 0.35 秒 | 未接原生热榜，不换身份继续请求 |
| B 站关键词搜索公开端点，Python | HTTP 412，约 0.20 秒 | 未接原生关键词搜索；热词路径不能代替它 |
| 小红书搜索页，Python | HTTP 200，约 0.67 秒，返回 HTML | 未确认可用匿名结果/正文；不把 200 当能力验证通过 |
| 小红书公开索引，`Python 学习` | Exa 免 Key一次，约 0.73 秒，主要是账号主页 | 保留有用的作者线索，不称已取得笔记正文 |
| 微博公开索引，`人工智能` | Exa 免 Key一次，约 1.16 秒，帖子与主页混合 | 作为索引线索，不称原生站内搜索或已读正文 |

两个索引问题均显式 free、禁用浏览器，实际带 Key API 为零。未增加用户凭据，也未修改用户配置。索引有结果不代表满足内容检索质量要求，尤其小红书样例未解决笔记正文证据缺口。

因此增加 `platform_item_type`，按已知 URL 形态标记 note_link、post_link、user_profile 等。账号主页仍可用于找作者，但不能用于回答“这篇笔记说了什么”。URL 类型本身也不证明页面当前可访问。

## 公开资料与实现参考

- [小红书账号 API](https://openaccount.xiaohongshu.com/docs/api-reference)列出授权/Token/用户基本信息接口；[scope 文档](https://openaccount.xiaohongshu.com/docs/scope)当前仅开放 basic_info，read_notes 标为规划中。这不是可直接匿名使用的通用笔记搜索 API，也不排除其他业务线存在各自授权接口。
- [NewsNow B 站实现](https://github.com/newsnext/newsnow/blob/main/server/sources/bilibili.ts)和[知乎实现](https://github.com/newsnext/newsnow/blob/main/server/sources/zhihu.ts)提供公开端点的实现参考。本项目独立实现 Python 适配，端点仍是实验性网页入口，没有开放平台 SLA。
- [NewsNow 微博实现](https://github.com/newsnext/newsnow/blob/main/server/sources/weibo.ts)依赖硬编码 Cookie；本项目不复制或使用该凭据，也不将其作为免配置基础能力。
- [V2EX API 公平使用规则](https://www.v2ex.com/p/7v9TEc53)说明限额与用途边界。适配仅用于按需获取用户所问的热点线索；本报告不再发布话题正文、用户档案或完整榜单数据。

## 实现与验收

- 独立 `trending` 命令只访问指定平台：一次 HTTP、默认 8 秒、零重试，不读取用户配置或 Key，不增加普通搜索的请求数。
- 三源每 2 秒最多一次，跨进程串行；401/403/412 暂停 15 分钟，429/503 遵守 Retry-After，无说明时暂停 60 秒。暂停不通过切换 Cookie、代理或浏览器规避。
- 明确空数组可以成功且 empty:true；异常形状、错误码、验证页不能伪报成功空榜单。结果解析失败仍计实际 HTTP 尝试。
- 离线平台目录分别声明关键词覆盖与 native_trending，不把热榜接口加入 Smart 搜索源。
- 159 项离线测试通过，覆盖免费隔离、无配置/无 Cookie/无浏览器、顺序/广告/日期语义、坏数据、实际请求计数和拒绝冷却。CI 不执行线上请求。

最初三条在线适配及两条索引检查使用开发工作树，版本标签尚为 0.7.2；最终发布为 0.8.0。后续本机安装验收记录单列在[结构化记录](2026-11-05-public-platforms.data.json)，不混作首次耗时或重复算作更多题目。直接端点探测 6 组（探测工具内部重定向次数未计量），首次适配/索引检查共 5 次可观测 API HTTP；安装验收单列，文档查阅不在该统计内。

## 下一步顺序

1. 新闻机构公开 RSS/Atom、政府公告：补中文实时信息与原始出处，用真实新闻题检验日期和去重。
2. V2EX 最新话题/单条阅读，以及社区原文读取：提高从热点线索到可引用正文的完成率。
3. 小红书、微博原生动作：先核实公开可用入口或已有授权工具，再决定接入；登录与维护成本单独记录，不承诺匿名开箱即用。
4. 跨网络重复验收，观察错误率、延迟分布和字段变化。来源数量、榜单非空或一次调用成功都不替代答案质量评估。
