# Exa 限额故障注入与本地浏览器兜底

**简体中文** | [English](2026-11-03-fallback.en.md)

日期：2026-11-03。代码基线为 `4995609`，测试在 v0.6.0 基础工作树进行，对应改动发布为 v0.7.0。[脱敏数据](2026-11-03-fallback.data.json)区分最终离线断言、真实匿名 API 和两个真实浏览器观察；不包含网页正文、验证码 URL、Cookie、真实 Key 或用户凭据文件。

## 验收结论

**免费模式的付费搜索 API 隔离与路由故障恢复断言通过；本机当时的真实浏览器搜索可用性未通过。** 模拟浏览器返回结果的成功路径，不能代替真实浏览器可用性验收。

- 六家带 Key 服务均在内存中配置合成 Key，同时搜索策略设为 free。API 测试守卫在传输前拒绝任何带 Key 来源和非空凭据。测试不读取用户凭据文件；实际浏览器进程不继承服务 Key 或云浏览器/AI 网关配置。
- 模拟 Exa 的 HTTP 限额与 MCP/tool 应用层限额，验证记录冷却、后续跳过、到期允许试探。应用层错误没有伪造成 wire HTTP 429。无恢复说明时暂缓 15 分钟，不声称届时额度已经恢复；明确 Retry-After 优先。
- API 返回可用结果时浏览器不启动。API 互补失败但已有首源证据，也不启动浏览器。用户显式指定来源、来源/HTTP/时间上限及禁用偏好均保留。
- Exa 耗尽、公开 RSS 跑题后，模拟 browser 返回可用来源；再次查询直接跳过暂停中的 Exa，公开备用失败后仍能走模拟 browser。两次付费搜索 API 尝试均为 0。
- 真实浏览器路径已执行，但 Bing 当时返回空壳或超时；均正确报告失败，未把空页面当“无资料”或成功。没有切换身份、导入登录态或处理验证码。

本地 135 项离线测试通过，其中新增 15 项覆盖额度故障注入、跨查询暂停、免费隔离、API 优先、浏览器按需、浏览器环境/命令/关闭、预算、禁用和协议错误。它们不证明网站的长期可用性。

## 快速路径与重量的权衡

| 条件 | 默认执行 | 浏览器 |
|---|---|---|
| 平台问题有匹配原生 API | 直接走平台公开接口 | 成功不启动 |
| 普通 Smart、有已启用 Key | 配置规则选择 API | API 返回可用结果时不启动 |
| 官方/最新信息需要互补 | 在预算内使用第二个 API | 不为互补启动 |
| 没有 API 可用结果且 browser 可用 | 默认两条兼容 API 后才搜索浏览器 | 一次导航，结束关闭 |
| 已知 Exa 额度受限 | 直接跳过 Exa | 仍先走其他兼容 API |
| 浏览器刚失败/被验证 | 冷却或停用，不反复开浏览器 | 60 秒或 15 分钟暂停 |

这里的“可用”是有效非空结果及保守跑题检查，语义完整度与事实仍由 Agent 核对。浏览器不会被当作质量更高的默认源。用户明确选择 browser（本次或已保存默认源）时，可覆盖默认顺序。

自动调用默认最多 3 个总来源、总调度 45 秒，API 每源最多 8 秒，浏览器工作最多 15 秒，再受 --timeout 和剩余时间裁剪，另有最多 6 秒关闭宽限。已保存的 1/2 源上限不擅自放宽；2 源有浏览器时是一条 API 加浏览器。无浏览器时最多三个 API。网络/DNS 与 socket 读取不是硬进程截止，不宣传为服务等级保证。

程序不在正常查询前跑联网体检。只做本地能力/暂停文件检查；没有浏览器运行时启动、模型重排、服务自建或安装依赖。浏览器仅在兜底调用时启动，不安装/登录/读取个人 Chrome 配置，使用唯一会话与空配置。仅固定 open、wait、DOM eval、close，不调用 agent-browser chat。关闭命令失败会保留标记，另设 20 秒空闲退出，不能伪报已成功关闭。

## 测量结果

任务：`Python asyncio TaskGroup documentation`。下表是各一次观察，不是同质量延迟排名。模拟行只验证调度，不能拿毫秒数与真实网络比较。

| 检查 | API HTTP 尝试 | 带 Key API 尝试 | 浏览器导航 | 结果 |
|---|---:|---:|---:|---|
| 模拟健康免 Key API | 1 | 0 | 0 | 返回，未启动浏览器 |
| 模拟 Exa 限额＋RSS 跑题 | 2 | 0 | 1（模拟） | 浏览器模拟来源返回，保留失败历史 |
| 再次查询，Exa 已暂停 | 2 | 0 | 1（模拟） | 跳过 Exa，备用失败后恢复 |
| 真实免 Key API | 1 | 0 | 0 | 约 1.36 秒，3 条相关文档链接 |
| 真实 browser：初次 | 2（模拟） | 0 | 1（真实） | 约 9.64 秒；空壳，失败；3 秒关闭宽限未确认关闭 |
| 真实 browser：关闭修正后 | 2（模拟） | 0 | 1（真实） | 约 11.17 秒；工作超时，失败；6 秒关闭宽限取得正常确认 |

浏览器诊断命令使用 --timeout 8，进一步将其工作预算裁剪到 8 秒；这与发布默认 15 秒不同。两次浏览器测试的 API 故障均为本地模拟，没有真的耗尽 Exa，也没有实际请求 Bing RSS/DDG。真实 API 行为单独一次匿名 Exa 请求。浏览器页面与资源子请求数量不可观测，数据中为 null，不冒充“一次 HTTP”；浏览器导航/本地命令与 API budget 分别计数。

API 检索约 1.36 秒时，本地浏览器启动为零；失败兜底明显更慢，说明应保留 API 优先、一次兜底和失败冷却。浏览器没有在这轮取得可接受搜索结果，因此不能承诺在该网络下补足所有检索，也不能宣称其效果超过 API。

## 费用与失败边界

已验证的边界是本工具带用户 Key 的搜索 API 尝试数为零；不是模型 Token、宿主订阅、本机计算或所有网络活动零成本。Smart/quality 中用户启用的 Key 仍可按原偏好使用；free 不因此升级到带 Key 的 Exa 或其他付费服务。

Exa 的匿名托管 MCP 是限额免费，官方说明见[文档](https://exa.ai/docs/get-started/exa-mcp)。浏览器利用已有[agent-browser](https://agent-browser.dev/) 与本机 Chrome，不自建搜索索引。网站或网络拒绝访问时只能报告缺口，不能靠轮换会话、代理或验证码处理制造“保障”。

## 复现

```bash
# 完全离线：模拟 API 和浏览器，守卫阻止付费请求
python3 scripts/evaluate_fallback.py --output ../fallback-offline.json
# 单独真实匿名接口和真实浏览器；浏览器可能因网络条件失败
python3 scripts/evaluate_fallback.py --live-api --live-browser --output ../fallback-live.json
python3 -m unittest discover -s tests -q
```

脚本 ok 表示路由安全断言通过，`live_browser_usable` 单独表示真实浏览器可用性；本轮为 false。测试缓存隔离，不修改用户 Key、偏好或实际冷却文件。
